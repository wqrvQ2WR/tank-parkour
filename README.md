# TANK PARKOUR

three.js로 만든 3D 탱크 파쿠르 타임어택. 테일즈러너처럼 발판을 뛰어넘으며 코스를 완주하는 게임인데,
달리는 게 사람이 아니라 80톤짜리 탱크다.

`index.html` 하나로 끝. 빌드 없음, 의존성은 CDN의 three.js 하나.

## 실행

```bash
python3 -m http.server 8123
```

브라우저에서 `http://localhost:8123` 을 연다. (마우스 시점 조작에 포인터락을 쓰기 때문에
`file://` 로 직접 열어도 되지만 로컬 서버 쪽이 안정적이다.)

## 조작

| 키 | 동작 |
|---|---|
| W A S D | 이동 (카메라 기준) |
| SPACE | 점프, 공중에서 한 번 더 누르면 더블점프 |
| SHIFT | 부스터 (게이지 소모, 최고속 27 -> 44) |
| 마우스 | 시점 회전 + 포탑 조준 |
| 좌클릭 / F | 주포 발사. 쏜 반대 방향으로 반동을 받는다 |
| R | 마지막 체크포인트로 복귀 |

모바일은 자동으로 터치 UI가 뜬다. 왼쪽 가상 스틱으로 이동, 오른쪽 화면 드래그로 시점,
FIRE / JUMP / BOOST 버튼.

### 반동 점프

주포를 아래로 쏘면 그 반동으로 탱크가 솟아오른다. 더블점프로도 안 닿는 발판은 이걸로 넘는다.
포탄은 3발까지 장전되고 1.5초마다 한 발씩 다시 찬다. 체크포인트를 지나거나 에너지 셀을 먹으면 즉시 보충.

반동은 60이다. 수직 아래로 쏘면 **약 19 높이**까지 솟는다. 그냥 점프(5.0)의 4배다.
비스듬히 쏘면 9 정도 뜨면서 그만큼 앞으로 튕겨나간다.

### 동전과 차고

코스에 동전 112개(합계 139개 값)가 깔려 있다. 대부분 1개짜리고, 위험한 자리 세 곳에 10개짜리 큰 동전이 있다.
줍는 즉시 지갑에 들어가고 localStorage에 저장된다. 판이 끝나도 사라지지 않는다.

메뉴의 `차고`에서 동전으로 탱크 도색을 산다. **도색마다 능력치가 다르다.**

| 기본 도색 | 0 | 무난하다 | 전 항목 표준 |
| 라임 소다 | 40 | 가볍다 | 반동 +30%, 가속 +15%, 점프 +14%, 접지 -38% |
| 딸기 우유 | 80 | 공중 제어 | 공중 제어 +70%, 가속 +12%, 반동 -10%, 속도 -4% |
| 심해 | 140 | 부스터 | 부스터 소모 -34%, 회복 +30%, 속도 +20%, 점프 -4% |
| 골드바 | 250 | 무겁다 | 가속 +45%, 접지 +60%, 피격 넉백 -55%, 반동 -40%, 속도 -5%, 점프 -6% |
| 무지개 | 400 | 전천후 | 전 항목 소폭 상승, 부스터 소모 +35% (색이 계속 순환한다) |

그건 상점에 올리면 안 되는 물건이기 때문이다.

전부 모으려면 910개, 완벽하게 다 주우면 7판 정도 걸린다.
`기록 초기화`는 완주 기록과 고스트만 지운다. 동전과 산 도색은 남는다.

## 맵 만들기 · 링크 공유 · 제작자 고스트

메뉴의 `맵 만들기`로 직접 코스를 짓는다. 조준선을 보고 놓는 방식이라
화면 중앙 레이가 곧 커서다. 키보드와 마우스가 필요하다.

| 조작 | 동작 |
|---|---|
| 클릭 | 조준한 자리에 조각 놓기 (처음 클릭은 마우스 잠금) |
| 우클릭 / X | 조준한 조각 지우기 |
| WASD · Space · Ctrl | 자유 비행 (Shift 가속) |
| 1~0 · - = \\ ` | 조각 고르기 |
| `[` `]` / `,` `.` | 가로 / 세로 크기 |
| Q / E | 바닥 높이 |
| R / F | 회전 / 기울이기 |
| Ctrl+Z | 되돌리기 |

조각은 발판, 파란 발판, 램프, 외줄 다리, 움직이는 발판, 부스터, 점프대,
회전 강철봉, 동전, 큰 동전, 에너지 셀, 체크포인트, 피니시, 시작점 14종.
체크포인트 번호는 z 순서대로 자동으로 매겨진다.

### 링크 공유

`공유 링크`를 누르면 맵 전체가 URL 해시에 담긴다.
JSON을 `CompressionStream('deflate-raw')`으로 압축하고 base64url로 실어서,
**기본 코스(172조각)가 1.8KB**, 60초짜리 제작자 고스트까지 붙여도 **3.2KB**다.
의존성 없이 브라우저 내장 API만 쓴다.

### 제작자 고스트

에디터에서 `테스트 주행`으로 한 번 완주하면 그 주행이 맵 식별자별로 저장되고,
그 뒤에 만든 공유 링크에 같이 실린다. 링크를 받은 사람은 제작자의 주행을
반투명 유령으로 보면서 달린다. 고스트는 URL 용량 때문에 20Hz -> 10Hz로 솎고
좌표를 0.25 단위 정수로 양자화한 뒤 차분만 남긴다.

기록과 고스트는 맵마다 따로 저장된다 (`tankparkour.best.<맵id>`).
공유받은 맵에서는 내 기록이 있어도 제작자 고스트를 우선 보여준다.

## 코스

기본 코스는 7개 구간, 체크포인트 6개, 에너지 셀 13개.

체크포인트는 리스폰 지점일 뿐이라 **다 안 거쳐도 골인은 인정된다.**
반동 점프로 지형을 질러서 코스를 건너뛰는 것도 기록으로 남는다.

1. 스타트 플라자 + 직선 징검다리
2. 지그재그 계단
3. 좌우로 움직이는 발판 다리
4. 오르막 램프 + 부스터 대점프
5. 회전 강철봉 광장 (맞으면 튕겨나간다)
6. 좁은 외줄 다리
7. 점프패드 타워 -> 마지막 활강 -> 피니시

완주 기록과 고스트(자기 최고 기록의 주행 궤적)는 localStorage에 저장된다.
다음 판부터 반투명한 파란 탱크가 자기 기록대로 같이 달린다.

## 코스 검증 (`bot.js`)

브라우저 탭이 백그라운드면 `requestAnimationFrame`이 멈춰서 눈으로 검증하기가 어렵다.
그래서 `window.__game.step(dt)` 훅으로 시뮬레이션을 프레임 단위로 직접 돌릴 수 있게 해뒀고,
`bot.js`가 그걸 이용해 오토파일럿으로 코스를 검증한다.

게임 페이지는 `bot.js`를 로드하지 않는다. 콘솔에서 직접 부른다:

```js
await import('/bot.js?v=' + Date.now()); window.__botResult
```

- 구간별 테스트: 각 발판에서 다음 발판까지 실제로 갈 수 있는지 하나씩 확인
- 전체 완주 테스트: 웨이포인트를 따라 처음부터 끝까지 달려본다

이걸로 잡은 것들:

- 램프 두 개가 반대 방향으로 기울어져 있어서 오르막이 내리막이 돼 있던 것
- 점프로 넘을 수 없는 간격 몇 군데
- **포신 상하각이 뒤집혀 있던 것.** 카메라로 아래를 조준하면 포신은 위로 들렸다.
  "아래로 쏘면 위로 솟는다"는 핵심 조작이 실제로는 반대로 동작하고 있었다
- **수평 속도 상한이 외력을 한 프레임 만에 지우던 것.** 부스터 패드가 52를 넣어도
  다음 프레임에 27로 잘려서 패드가 사실상 아무 일도 안 하고 있었다.
  이제 조작으로는 상한을 못 넘되 패드/반동 같은 외력은 살아남고 공기저항으로 서서히 빠진다
- **가변 점프 감쇄가 점프패드와 포 반동에까지 걸리던 것.** 스페이스를 안 누르고 있으면
  상승 중 매초 34씩 깎는 로직이 외력에도 적용돼서, 점프패드가 설계값 17이 아니라 14밖에 못 띄우고 있었다.
  타워 발판 높이가 12라 여유가 3밖에 없었다. 이제 내가 누른 점프에만 걸린다 (`player.cutJump`)
- **창이 0x0으로 보고되면 카메라 투영행렬이 통째로 NaN이 되던 것.** `aspect = 0/0`.
  숨겨진 패널이나 임베드 환경에서 이러면 레이캐스트가 죽어서 에디터가 아무 반응도 안 한다
- **에디터 삭제가 조준한 조각이 아니라 근처의 다른 조각을 지우던 것.** 히트 지점과의
  거리로 추측하고 있었다. 이제 메시에 소유 조각을 새겨서(`userData.piece`) 정확히 지운다
- **맵을 데이터로 옮기면서 체크포인트 복귀 높이가 1.05만큼 어긋난 것.** 발판 윗면 기준
  오프셋을 잘못 잡았다. 지문 비교로 잡았다

### 도색별 능력치를 넣고 나서

도색마다 능력치가 다르면 "이 도색으로는 코스를 못 깨는" 경우가 생길 수 있다.
봇을 도색별로 돌렸더니 도색마다 다른 구간에서 실패했는데, 전부 봇 문제였다:

- 목표에 가까워져도 가속을 안 놓아서 발판을 지나쳐 버렸다 (가속이 높은 도색일수록 심했다)
- 이동 발판 구간에서 발판의 기준 좌표(x=0)에 탱크를 올려놓고 시작했다. 발판은 ±12로
  움직이니까 매번 허공에서 떨어지고 있었다
- 피니시 게이트를 지나면 물리가 멈추는데(완주 처리) 그걸 실패로 셌다.
  체크포인트 없이도 골인되게 바꾼 뒤로 이 구간은 아예 측정이 안 되고 있었다

이동 발판 구간만은 봇으로 결론이 안 나서 기하로 직접 따졌다(`reach-test.js`).
발판 위상을 40초어치 훑어서 매 순간 필요한 도약 거리를 계산했더니 **최대 14**였고,
가장 나쁜 도색인 골드바의 실측 비거리가 **20.1**이다. 모든 도색이 모든 위상에서 통과 가능하다.

성능 측정 하네스에서도 세 가지를 고쳤다. 발판 밖으로 떨어진 뒤의 속도를 재고 있었고,
되감기 구간이 동전 아치와 겹쳐서 부스터가 계속 차고 있었고, 되감기 레인이 피니시
트리거를 지나서 측정 도중 게임이 끝나고 있었다.

검증 스크립트는 셋이다. 전부 콘솔에서 `await import('/파일명.js?v=' + Date.now())` 로 돌린다.

| 파일 | 결과 변수 | 하는 일 |
|---|---|---|
| `bot.js` | `window.__botResult` | 구간별 통과 테스트 + 전체 완주 시도 |
| `seg-test.js` | `window.__segResult` | `window.__SEGCASES`에 지정한 구간만 5번씩 반복 |
| `recoil-test.js` | `window.__recoilResult` | 포신 상하각 방향과 반동 도달 높이 측정 |
| `editor-test.js` | `window.__edResult` | 에디터 -> 테스트 주행 -> 링크 -> 링크 복원 왕복 |
| `skin-test.js` | `window.__skinResult` | 도색별 최고속/점프/반동/부스터 실측 |
| `reach-test.js` | `window.__reachResult` | 이동 발판 구간을 도색별로 건널 수 있는지 기하 계산 |

`bot.js`는 `window.__botFull = false` 로 전체 완주 테스트를 건너뛸 수 있다 (구간 테스트만 빠르게).

`editor-test.js`는 에디터로 맵을 짓고 -> 테스트 주행으로 완주하고 -> 공유 링크를 만들고 ->
그 링크를 다시 풀어서 원본과 같은지까지 한 번에 확인한다.

`seg-test.js`는 특정 구간만 5번씩 반복해서 통과율을 본다. 회전봉/이동발판 구간은 위상에 따라
3~4/5로 갈리는데, 이건 타이밍을 보고 뛰라는 의도된 난이도다.

## 물리 수치

중력 62, 점프 초속 25 -> 체공 0.81초, 점프 높이 5.0.
평지 최고속 27, 부스터 44, 부스터 패드 52, 포 반동 60.
평지 점프 비거리는 약 21, 부스터 패드를 밟으면 약 42.
코스의 모든 간격은 이 범위 안에서 잡혀 있다.

금속 재질(골드바/심해 도색, 동전)은 반사할 환경이 없으면 새까맣게 렌더된다.
하늘 셰이더를 `PMREMGenerator`로 구워서 `scene.environment`에 물려 해결했다.

## 맵 데이터 구조

기본 코스도 에디터로 만든 맵과 똑같이 "조각 배열"이다. 하드코딩된 코스가 아니라
`defaultCourse()`가 조각을 쌓아 올리고, 그 결과를 그대로 직렬화할 수 있다.

```
{t:'p', x, y, z, w, d, s, h?, a?(x기울기), g?(y회전), pil?(기둥), bm?(외줄), mv?[진폭,속도,위상]}
t = p 발판 / b 부스터 / j 점프대 / c 동전 / e 에너지셀 / k 체크포인트 / f 피니시 / x 회전봉 / s 시작점
```

`buildMap(pieces)`가 월드를 통째로 지우고 다시 짓는다. 코스가 만드는 오브젝트는
전부 `worldGroup` 아래로 들어가서 한 번에 정리된다.
